## Public

### Purpose

The record store's assembly and the world its tests ask. It builds every module of the record store on one Durable Object's storage, in the modules' order; migrates them before any request; composes their registrations and ops maps into the one route map; passes every store request through `store-door`'s frame; and publishes `storeWorld()`, the real store with a pinned clock, a real claim, and a copy for each test. It imports no platform module, so it runs in plain node; `plane` hosts it as the Durable Object class and the Worker's entry.

### Provides

Terms. The **assembled store** is what `assembleStore` answers (R1). The **owner map** is the arms of the ops whose owners export a service and no ops map (R86). A **world** is what `storeWorld()` answers (R90); `store-request` adds the door, the sign-ins and the recipes over it. The store's request from a page's is made by `store-request`'s `innerRequest` (K5052 (1)). To **compose** a module is to build it on the object's storage in R2's order (its place in `build/modules.json`), run its migration as R3 says, declare its tables to purge through `record-core`, start it so its registrations are held before the first request, hand it the instances it reads (one instance per host) and spread its ops map, if it has one, into R6's route map, so its ops reach their handlers through `control-plane`'s door.


**The assembled store: `assembleStore`** (K5046 (a))

- **R1** (was `plane` R1 and R2, in part; `releaseKeys` K5226) `assembleStore(ctx, env, {deliver, releaseKeys})` builds every module of the record store on one Durable Object's storage and answers the assembled store `{routes, dispatch, namespace, nowMs, read}` (the route map R6, `dispatch` R7, `namespace` R4, `nowMs` R5, `read` R8). `ctx` is the object's state as the runtime hands it (the surface R90 lists); `env` is its bindings (`STORE`, `CAPTURES`, `ACCOUNT_SEAL_SECRET`, `RECEIPT_SIGNING_KEY`, `INSTANCE_NAME`, `AGENT_WORKER`, `FILE_SCANNER`, `CAPTURE_CREDENTIALS_KEY`, `OWN_HOSTS`, `BIO_NOW_MS`), each optional and read where it is used; `deliver`, optional, is `control-plane`'s owed-render delivery (`deliverOwedRender`, `control-plane` R124), handed to the owed-work ledger: absent, a ledger row that needs it stays owed (R67); `releaseKeys`, optional, is the keys a release notice is verified with, handed to `instance-setup` (a test's keys; the class hands none). It builds the modules in the order of R2, migrates them as R3 says, hands the alarm to `scheduler`, and starts `instance-setup` once per object (`instanceSetupOf(ctx, env).start()` inside `blockConcurrencyWhile`), whose routes (`instanceSetupOps`) are part of R6's map. Called twice over one storage it starts `instance-setup` once and migrates idempotently. A module that fails to build, or a migration that throws, leaves the object unanswering; no store is answered. The Durable Object class (`plane` R1) calls it once per construction and holds no construction of its own. Test: `plane`'s construction tests, re-pointed at `assembleStore`; control: two calls on one database leave one `instance-setup` start and no second migration.
- **R2** (was `plane` R2) At construction, before any route or alarm can run, every module is built on the object's storage in the order `assembleStore` builds them, so every listener, promotion step, count, grammar and fact a module registers at start is held before the first request, each slot ordering its registrations by the modules' total order (`member-roster` R27), never by construction order: record-core handed the evidence bucket (`env.CAPTURES`) and its key prefix (`<namespace>/captures/`, the namespace being the object's own name, `bio` or `scratch`, else `bio`); `store-door`'s promotion step (its R5) at the rank `STEP_ORDER` gives it, after every module of layers 1 to 10 and before the first of layer 11; `queue` and `tasks` creating their tables (queue R36, tasks R8). A factory a module's `deps` are read from on its first call is built first with them.
- **R3** (was `plane` R3) The migration pass runs once per construction inside `blockConcurrencyWhile`, before any request: record-core's `RECORD_SCHEMA` first, then each owner's `migrate()` in R2's order, additive columns added before and after the tables, so a store written by any earlier release opens; then `scheduler`'s `start`. - **R4** (was `plane`'s `#ownNamespace`) `namespaceOf(ctx, env)` (exported, pure) answers the logical name of the object the runtime says it is, asked of the runtime and not remembered: `bio` or `scratch` when `ctx.id` equals `runtime-limits.storeId(env, name)` for that name (the generation `~g<n>` being on the room's name only), else `null` for any other object (a suite's private instance), never a guess.
