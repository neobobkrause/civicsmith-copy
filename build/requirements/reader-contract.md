# reader-contract — requirements

**Status** · Split from `reading-pipeline` by BOB on 4 Nov 2026 (PR 274; the split proposal on PR 272): R45–R58 and R60–R67 moved here word for word, with their ids and marks. An id named here without a module is `reading-pipeline`'s (R1–R44, R59, R68 stay there). Its history and rulings: `docs/requirements-notes/reader-contract.md`.

#### The reader contract and the readers within the alpha (fix round 9, GAP-1.8; K4831, K4834, K4837)

- **R45** (G132, G130, G129; 2c item 7; K4834) **One reader contract over a range source.** `plan(source) → {kind, pages|rows, verdict, mode}` and `read(source, cursor, budget) → {units, next, more, final?, counters: {written, skipped, owed, failed}}`, `source = {size, readRange(offset, length)}` (`acquisition` R113: whole or in parts alike, hidden), the document's facts, the fleet and the view handed beside it as R24 lists. A capture's bytes are read only through `source.readRange`, never by resolving parts and never by loading the object whole for a kind that reads in ranges. `plan` reads only a head range and a tail range and the declared size, no body: `kind` is detected from them (R2; an image asked before a PDF or a web page, an office or OpenDocument file above 8 MiB recognised by its tail directory), `pages` or `rows` the declared count, `verdict` `{ok, size, limit, bound_key}` the size against the kind's bound (`READ_BOUNDS`, `statement`), `mode` the grain the kind is read in (pages, rows or byte windows). `read` takes `cursor` null for the first piece and answers `next` (the cursor for the next, opaque), `more`, `final` when the entry ends (a stated end included) and `counters`: units `written`, units stated unread `skipped`, units owed to a later piece or to OCR `owed`, units whose read failed `failed`. `budget` is `{bytes, objects}`: a step's cost is the bytes it decodes plus the objects it walks, counted, never a wall time (R-CLOCK). A whole read is a one-piece range: the three read modes this module had (the whole read, the read by cursor, the held read) are retired into this one, and a source that cannot answer a range is a failed reading, `transient` (R37). Test: the same corpus file read in one piece and in ranges gives the same units, field for field; a source counting its range reads shows no read past the head, the tail and the pieces asked; `plan` of a 40 MB file reads two ranges. Control: a file under every bound reads in one piece with `more: false`. (K4868, K4894) The range source reads the parts a document states first, each by a ranged get, and asks the store nothing of the whole; a part not held or short leaves the range to the whole. A CSV past `WHOLE_READ_MAX` and within its bound (`READ_BOUNDS` csv) is read from its first piece by range (a probe, the entry's dialect over it, the head to a record boundary giving the reading's facts, each piece a byte window), no piece holding the object or its text; a read with no cursor of such a CSV answers a reading not yet done, `failure: "transient"`, basis "read in pieces", which the ledger reads by pieces and no member reads as a failure. Test: `csv-range.test.mjs`.
- **R46** (G129a, G102; K4803, K4807 (4), K4831 (6)) **A piece that advances nothing ends the entry, stated.** The step wrapper asserts `next > cursor || final`: a piece whose `next` is not past its `cursor` and that is not `final` is never `more`, and `rangePieceAnswer` computes `next` from the advance made and not from the range asked for. An encrypted PDF that needs a user password ends in one piece, `final`, `PASSWORD_REQUIRED` ("needs a password"), and is never "being read" after; the guard is generic, any piece that advances nothing ending the entry stated. A file with an empty user password has its text pages read (tier 2 decrypts) and its scanned pages stated unread (the alpha, until N24's Stage 3), neither looping. Test: `r8-liveness.test.mjs` through the ledger's ticks: an RC4-128 empty-password file (5 text pages, 2 scans) and an AES-128 user-password file (PDF C11, C14): six ticks never the same cursor twice, the user-password file ends in one tick; a stub reader answering `count: 0` ends stated. Control: a file whose every piece advances is read to its end as before. (fix round 9, G155; K4958) The `PASSWORD_REQUIRED` / `ENCRYPTED` statement holds for a whole read as for a range (`reading-pipeline/index.mjs:3091` maps it only inside `rangeScope`): an encrypted PDF read whole ends stated with the code, never with prose from the text layer.
- **R47** (G128d, G128e, G128g, G128h, G134d; K4831 (7)) **Units are chunked, never cut, and each names its kind.** A line, paragraph, page, slide or sheet block over `CAPTURE_TEXT_UNIT_CAP` characters is carried as consecutive units of the same element (`run` 0, 1, ...), broken at a space with an overlap or at a stated seam so that a phrase across a seam is found; no unit is `truncated`, and no piece's cap cuts one (`extraction` R22). A unit is `{extent, seq, text, kind}`, `kind` one of the closed list `body`, `footnote`, `endnote`, `header`, `footer`, `comment`, `tracked_deletion`, `text_box`, `speaker_note`, `master_text`, `cell_note` (`body` when the reader names none), and `allUnitsOf` accepts every kind, so every part a reader emits (`office-readers`, `odf-reader`) reaches the index with its kind. A sheet's units carry their row numbers and keep their empty cells; a sheet block states `lineRows`, its per-cell `undetermined` list stored beside it. An optional part (cells, page boxes, image placements) that would take a reading past the stored bound is omitted with a statement and its units stay (`extraction` R97); a reading over 1 MiB is never replaced by a statement without units. Test: PDF A10, DOCS T5, P2, T14 and `red.mjs N15` (a 300,009-character line found at its last word; a 3 MB line without spaces; a phrase across a seam); DOCS O4, P3, D1, H6 (a footnote's figure found, its unit's `kind` `footnote`); DOCS O3 (tables of 500, 1,500, 3,000 and 10,000 rows with INTRO and ENDMARKER paragraphs: the ENDMARKER found); SHEET J-10 (first, middle and last mark found and the hit's extent contains the row). Control: a unit under the cap is one unit, `kind` `body`. **Amended (fix round 9, G166; K4985):** `allUnitsOf` makes no `body` unit of a paragraph a part names in its `paras` (`office-readers` R38), so each word is one unit of one kind. Test: a reading whose `text_box` part names paragraph 3 has no `body` unit for paragraph 3. Control: without `paras` every paragraph stays a body unit.
- **R48** (G128a, G128b, G128g; K4837) **Completeness is computed from the counters and from nothing else.** `completenessOf(counters, {more, final, refused}) → "whole" | "partial" | "stated" | "none"`: `whole` exactly when nothing more follows and `skipped`, `owed` and `failed` are all 0; `partial` otherwise; `stated` for a reading refused whole (`final` with a reason, no units); `none` when nothing was offered. A page owed to OCR (`tier3_candidate`, `ocr_left`, `unread_pages`) and an unread picture inside a text page (`image_content_undetermined`, `image_unread`: a page that is a picture of a table under a text title) are counted `owed`, so neither reading is ever `whole` before its last OCR. Test: SCAN C1, C4 and C11, C10 (a 30-page scan, 24 OCR'd: `partial`, `owed` 6; a text page with one large image: the image counted unread); a CSV of 18,098 rows: `declared.rows` 18,098 and `undetermined` 0 (a CSV block's repeated header is no row, R41). Control: a fully read text is `whole`.
- **R49** (G131g, X9; BOB's under K4628, reversing BOB #32) **Every text is decoded by one rule.** Text read here (a plain text, CSV, HTML, JSON, XML, a part's `.rels` or `document.xml`) is decoded by `ooxml.decodeText` (`ooxml`'s one decode rule; `acquisition` R120): UTF-8 with or without a BOM, UTF-16 with or without a BOM, or the declared or detected legacy charset (windows-1252, ISO-8859-x). The reading states the encoding (`encoding` and whether it was `assumed`, which `screens-inquiry` R134 draws) and, for a window whose detection differs from the file's, the offsets (`disagree`); a replacement over 0.5 % of the characters makes the reading `partial` with the count; an encoding it cannot decode is `ENCODING_UNSUPPORTED {name}`, never replacement characters with `failure` null. `text-chain` no longer counts U+FFFD or NUL as glyphs. Test: DOCS T7, H5, D5, the encoding matrix at 100 KB, 3 MiB and 9 MiB as upload and fetch: the text equals the truth or states the refusal. Control: UTF-8 is read as before.
- **R50** (G131i, G131h; K4834) **Text, JSON and XML are read in byte windows with a carry, to the standard.** A plain text, a JSON document and an XML document are read in byte windows, the carry being the unfinished line, quoted run or tag at a window's end; their active bound in `READ_BOUNDS` is the standard's (50 MB for the light kinds, K4834), and a file above is refused with its size and the limit (R54), nothing owed. Later pieces hand an entry no more than its window (at most 5 MiB), and the bytes pulled over a whole read are at most twice the file's, counted. Test: a text, a JSON and an XML of 50 MB read in windows with the last token found by `op=search`; 50 MB plus 1 refused with the figure; the carry cases (a multi-byte character, a tag split by a window edge, at the edge and one either side); bytes pulled at most twice the file; at a scaled window in the job and at full size in the corpus set. Control: a file under a window is one piece. (job 40, K4909) A text read by range from its first piece (past `WHOLE_READ_MAX`, within the text bound) decides its grain over its head, digests and counts its head (`text_scope = {bytes: [0, end], of: size}`), has `words_total` null in its first reading and states it in the last piece; a run with no separator in a window is carried as consecutive units of the same element (`run` 0, 1, ...), the very chunks the whole run gives. Past a whole read, a text in UTF-16 or a single-byte charset is read by range from its first piece as UTF-8 is, the head's encoding kept in the cursor and stated; another multi-byte charset over `WHOLE_READ_MAX` is stated with its size and bound (K4906). (T53, R66: the text bound is 100 MB, replacing the 50 MB here.)
- **R51** (G131f, S-34, X31) **HTML is read by one streaming pass, linear in its bytes.** The visible text of an HTML page is made by a single pass whose work is counted in elements and is linear in the page's size, so closed nested `<div>` to depth 8,000, 16,000 unclosed `<p>` and a 4,000-item unclosed `<li><a>` list cost no more than their size; a table keeps its rows and columns (a cell is not a paragraph), and a list or table of links inside the page's content is kept as passages (only links inside navigation furniture, R32, are dropped). Later ticks of an HTML file do not re-open and re-parse the whole file (R50's bytes bound). Test: DOCS H4 and SHEET D02 (a 500 x 20 table; the deep and unclosed shapes): the stretch counted in elements between yields. Control: a page with no table or links reads as R32 states. (job 40, K4909) A table row is one paragraph, its cells told apart by a tab; a list, table or block holding one, of only links, is kept; a bar of links is furniture. (Fix round 10, cause 18b; K5053) A block inside a table cell (a `p`, a `div`, a list item) does not end the row: the row stays one paragraph with its cells told apart by a tab, and two blocks in one cell stay in that cell. Test: `<table><tr><td><p>a</p></td><td><p>b</p></td></tr></table>` reads the row `a` TAB `b`; a cell holding two `<p>` keeps its row; a 500 x 20 table whose cells hold `<p>` reads as 500 rows. (T51 fix round 10; READING-PIPELINE #40 J55 (a); K4630, K5211) **An HTML page within the text bound is read, never refused for its size.** HTML's active bound is the standard's text bound (R50's, 50 MB), as `plan()` reads it: a page past `WHOLE_READ_MAX` and within that bound, whole or held in parts, is read by this one pass in byte windows with a carry (an unfinished tag or entity at a window's end), the pass's state carried between windows, so its units equal the same page read whole; a page above the bound is refused with its size and the limit (R54). Test: an HTML page of 30 MiB (scaled in the job: a window below the page) read whole and in parts equals its single-window reading; 50 MB plus 1 refused with the figure. (T53, R66: the text bound HTML is read to is 100 MB, replacing the 50 MB here.)
- **R60** (fix round 10, cause 2b; K5055) **A size or structure refusal carries what its figure measures.** A reading refused for a bound carries `size` and `bound` with the `metric` they measure (`bytes`, `rows`, `columns`, `objects`, `cells`, as the reader that refused states), and its sentence names that unit: rows, columns and objects are never called bytes. A DOCX or PPTX refused for objects carries `n`, the count at which the walk stopped (250,001 for the bound 250,000), with the unit objects. Test: a CSV of 1,048,577 rows is refused with the metric `rows` and a sentence that does not say bytes; a DOCX of 300,000 paragraphs is refused with `bound` 250,000, `n` 250,001 and the unit objects.
- **R61** (fix round 10, cause 3; K5055; amends R54; `acquisition` R102 stands) **A file declared Word whose bytes are not OLE is stated legacy Word.** A file whose declared type is `application/msword` or whose name ends `.doc`, and whose bytes are not an OLE compound file, is stated final, not repairable, `UNSUPPORTED_FORMAT` with kind `legacy_word`, never "not read as text (non-textual or too large)"; an OLE file is stated as before, and a declared type that is not text is still not overridden by a name. Test: the text `legacy word text walk ` repeated, declared `application/msword`, and with type empty and name `x.doc`: each is `UNSUPPORTED_FORMAT` `legacy_word`; control: an OLE file is unchanged.
- **R62** (fix round 10, cause 9; K5053) **What the structure read repaired reaches the reading.** When the PDF structure read rebuilt a damaged or missing cross-reference (`xref_reconstructed`) or found pages missing (`pages_missing`, with the count missing and the total), the reading lists each note, so a screen can state that the file was repaired; a file with a sound cross-reference lists none. Test: a PDF with a damaged cross-reference, one with none, and one cut at 70 per cent list their notes (`pages_missing` 8 of 30 for the last); control: a sound file lists none.
- **R52** (G133f, X25) **Classification is a budgeted step.** `docprofile.doctypeFor` over a capture's text is given a head-and-sample above 2 MiB for every kind, and each detect a window and a work count, so a tick's classification is bounded by that count and not by the text (R42 holds: once per read). Test: DOCS T1, T4, Q1 by count: the classification work per tick is bounded, a 12 MB DOCX or HTML classified in bounded steps. Control: a short text is classified whole as before. (job 40, K4909) A text judged from a view states it (`classified_over`, and the sentence after the basis).
- **R53** (G129b, G129c; amends R37) **A failure at any tick is classified and a transient one is retried.** A transient failure at tick 2 or later (an R2 hiccup, a range read refused) comes back as `failure: "transient"` with its reason and the cursor kept, so the ledger tries again, and is never written as the end of the read (`more` 0) nor left `partial` without a reason. Test: PDF E7, SCAN E2, SHEET J-8, DOCS F1 (`storeFailAt` tick 3 and 2): retried and whole, or `final` with its reason. Control: a deterministic throw is `final` at once (R37).
- **R54** (G135a, G135b, G135d, G135e, G124a; K4831 (3)) **A refusal names its own cause, its figures, and what it cannot read.** Each refusal is its own statement: `TOO_LARGE {size, bound}`, `UNSUPPORTED_FORMAT {kind}`, `ENCODING_UNSUPPORTED {name}`, `ENCRYPTED`, `STRUCTURE_OVER_BOUND {part, bound}`; a size refusal carries the file's size and the limit (`READ_BOUNDS`' `statement`) and is worded with those two, never as "read" nor as "non-textual or too large" nor "(multipart)". The reason a member refused a picture (`refusal.render.reason`: `IMAGE_TOO_LARGE`, `TRUNCATED_IMAGE_DATA`, `UNSUPPORTED_JPEG_PROCESS`, ...) reaches the reading, and a refusal from a declared size is `final` (R37). A kind with no reader is named ("RTF is not read yet", email, legacy Word, TIFF, GIF, WebP, HEIC, BMP) and its reading is not `repairable`, so no "Read it" is offered where it cannot succeed. Test: SHEET C05, X05 (an 18,069,786 B CSV; a 33 MiB xlsx): the statement holds size and bound; SCAN A2–A11, A14 and DOCS R1–R3: the named sentence, no "Read it"; PDF A3. Control: a file within its bound is not refused. (K4868) A CSV over its bound (`READ_BOUNDS` csv bytes) is refused at once, `final`, `TOO_LARGE` with its size and that bound (`limit.csv.bytes`). (job 40, K4909) A size refusal of a capture in several parts says how many parts.
- **R55** (G126b, G126j; K4811 (6); amends R4, R37) **The inline pass makes no OCR call.** `read(..., {ocrInvocations: 0})` makes no OCR call: every page that would be asked is stated `ocr_left` and counted `owed`, a 3-page scan included, and `ocrInvocations` can express 0. The other member calls in a loop inside a member's request (tier 2, tier 4) are bounded the same way. The `owe` hook is retired: nothing here registers owed work, and the owing is `extraction`'s from `counters.owed` and `ocr_left`. Test: a counting OCR binding sees 0 calls from `captureupload`, `acquire`'s reading op, `extractread`, `readheld`, `pdfstructure&ocr=1`, `pagetranscribe` and the promote follow; `read(..., {ocrInvocations: 0})` states `ocr_left` for every page (SCAN A18, C1). Control: the ledger's continuation tick calls the OCR member as R4 states.
- **R56** (G137d, K4831 (10)) **Illegible pages are turned upright, then judged by one rule.** A page found turned is turned upright before it is read; the page's legibility is stored beside its text; under one fifth legible no text is stored and the page is stated; under four fifths the text is kept and marked partly legible; the same rule for a photograph and for a PDF page. A page the engine cannot orient is stated. Test: SCAN B1–B3, B8, B9 (inverted, blank, handwritten, faint; as pictures and as PDF pages): the same rule. Control: a legible page is read and not marked.
- **R57** (G128c, N3; amends R35, R40) **A PDF read in ranges completes its reading.** The facts of the file as a whole (`title`, `page_boxes`, `container_extent.images` with its `images_why`, `text_glyphs`, `words_total`) are carried by the pieces and completed as they arrive, so the stored reading equals the whole read's; `page_boxes` and image placements are rows of their own and never inside the reading JSON. Test: `red.mjs N3` and PDF A1, the 33-page agenda: the stored reading of a ranged read equals the whole read's, every file. Control: a one-piece PDF is unchanged. (K4868) The same completion for a CSV read by range: its last piece states `words_total`.
- **R58** (G136e, K4831 (6)) **A reading waits for no scan.** No reading step waits on a file's scan, grade or safe view, imports `file-safety`, or reads their state; a document held for review is still read. Test: SCAN E10 (a held document is read, `op=reading` whole); control: no `file-safety` import in this module's source.
- **R63** (K5157; walk-T51-final 06 §4) A text or HTML reading states its paragraph count in `container_extent.paragraphs` (R12), equal to the paragraph units it numbers (R32), as an office reading does, so content bounds a paragraph extent of it.
- **R64** (T53; T53-125; N1272; K4636, K5445, K5496, K5453 point 1; amends R1, R28, R44) **`interpretUnits(document, part, {evidence, env, view})` makes the facts the record relies on (entities, dates and figures) from one part's units only, mechanically.** A sheet part goes through `cellsInRange` (R44), a page, paragraph or slide part through the content type's reader (R1) handed that part's text units alone; the answer is `{part, entities, facts, cells?, at}` and says in `basis` which units it read. It makes no AI call and runs no tier above what the held reading already has. K5496, option A: names, organisations, dates and figures found when a non-sheet document is read stay the reading's own whole-document `entities` and `facts` (R1), used for search and stated as such, and are not a part's interpretation; interpretation is turning a part into facts the record relies on, and only this function does it. Test: a 40-page minutes fixture interpreted for pages 5 to 6 returns only entities whose units lie in pages 5 to 6, while the reading's whole-document entities are unchanged and still searchable; the same call for a sheet returns `cellsInRange`'s cells for the range and no others. Control: no `ai-*`, `agent-*` or `skills` module is in this module's `Uses` for this function (the register R16 test).
- **R65** (T53; T53-125; N1272; K5445 C) **`partsOf(reading, {kind})` names the candidate parts of a reading: its sheets with row blocks, its page ranges, its headed sections.** A part is named by the reading's own extents (units, headings, sheet names), in document order, at most 10,000 a document (a protective bound, stated with a `truncated` mark and the count when passed, never silent). A part has no weight. Test: a workbook of three sheets of 100,000 rows each is named as row blocks of the sheet's unit size in order; a PDF with headings is named by heading, and one without by page range. Control: a reading with no units names none and says so.
- **R66** (T53; N1266, N1267; K5427, K4906 (2), K4834; T53-124; `build/plan/beta/files/SIZES-N1267.md` §2, §3 (1), (2), (4); amends R50, R51, R54) **The text bound is 100 MB, and HTML is streamed to it.** The text kinds (text, JSON, XML, NDJSON, HTML and the text-like ICS, VCF, SVG, KML, GeoJSON, SRT, VTT, log and md) share one bound, 100 MB, the text row of `READ_BOUNDS` (`runtime-limits`; quoted here, never a literal), replacing the 50 MB of R50 and R51; HTML belongs to this bound, so no text kind has a lower one. A file of these kinds within the bound is read to its last line, searchable and citable, in byte windows with the encoding carried (R49, R50); a file above it is refused `TOO_LARGE` with its size and the limit (R54), from the declared size, before any byte is read, and nothing is owed. An HTML page past `WHOLE_READ_MAX` and within the bound is read by R51's one streaming pass in byte windows with a carry, never cleaned whole: what is held at any moment is a window and the pass's state, not the page, and the bytes pulled over the read are at most twice the file's (R50); the 24 MiB whole-page cleaning figure of GAP-1.8 (b) no longer stands for any size. Test: a text, a JSON, an XML, an NDJSON and an HTML file of the bound read in windows (at a scaled window in the job and at full size in the corpus set), the last token of each found by `op=search`; the HTML read in windows equals the same page read in one window, unit for unit, at a smaller scale; the memory held while reading the HTML page is the same at the bound as at a tenth of it, within a window; the bound plus 1 refused with its size and the limit before any read. Control: a text file of 50 MB plus 1, refused before this line, is read; a file of the bound exactly is read.
- **R67** (T53; N1266; K5436; RF10 of `build/plan/beta/files/REQ-format-registry-beta.md`; T53-124, T53-528; `acquisition` R138, `format-registry` R38, `extraction` R120) **A file held and named is a stated reading, and is read when a reader for its type arrives.** A capture `format-registry` answers `unlisted` (a type on no list, because no reader exists for it) is not a failure and not a refusal: its reading is final for now, has no units, and states `held_unread` with the type's plain name (`formatNameFor`, `setup-words` key by key, never an extension), no `failure`, no `TOO_LARGE`, and is not offered "Read it" while no reader exists. The answers are kept apart: `text` is read as text (R1, R32); `unlisted` is held (this line); `refused` is never filed, so never offered to `read`. When a reader for the type is added to the roster (`registerFormat`, `format-registry` R9) the next `plan` and `read` of the same capture, over the same stored bytes through `source.readRange` (R45), detect that type and read the file as any file of it, with no second upload; `read` itself is a pure function of the bytes and the roster, so the re-run is `extraction`'s act (R120) and needs nothing stored here. Test: a generated file of an unlisted type (an Outlook mailbox) read before any reader: `held_unread` with its name, no units, no `failure`; the same bytes read after a test reader for the type is registered: units, and the reading no longer states held. Control: a listed type reads as before; a file of valid text with no other structure is `text`, read, not held; a refused type is never given to `read`.
