# interface-shell — requirements

**Status and history** · in `docs/requirements-notes/interface-shell.md` (moved 4 Nov 2026 for the requirements cap), with the size estimate, the Uses, Satisfies and Suggestions.

## Public

### Purpose

The member interface's page and frame. It holds the member's session (R32), loads the member's words, draws the working frame and the path, routes among the screens the screen modules register, and gives every screen one way to read, to act, to explain and to refuse. Pure: it reads no table and writes nothing; every read and act is an op the plane serves, called from the browser.

### Provides

Terms. A **screen** is a registry screen (`docs/development/ux-substrate/screens/registry.json`, carried by `wizard-scripts` as `SCREEN_REGISTRY`, its R13). An **act** is a control that calls one op; a **read** is a call of a non-mutating op. **Words** are the interface's keyed words (R5). A **screen module** is one of `screens-settings`, `screens-intake`, `screens-daily`, `screens-inquiry`. The **phone width** is a viewport of 760 px or less (`civicsmith.css`' breakpoint). These terms are read by every screen module.

**The page: `interfacePage(screens)`**
- **R1** (fix round 3, C15, P2.4; K4353, K4356) `interfacePage(screens)` answers one HTML document: `<html lang>` the member's language once known (`en` before), one `<link rel="stylesheet" href="/app/assets/civicsmith.css">`, icons referenced from `/app/assets/icons.svg` (no inline copy of the sprite), and one `<script src>` loading the shell's script, composed from the shell's own functions and each registered screen's and held at an address that carries the release version, served unchanged for that release (`control-plane` R75); the module exports that script's source and its hash, which the page policy names in place of a nonce, and the page carries no inline script and no nonce slot. The page holds no member-facing text outside its words (R5) and no secret.
- **R2** (fix round 3, C15, P2.4; K4353, K4356; amends R1) The page names no resource on another origin in any `src`, `href`, `@import`, `url()` or fetch, and loads no typeface but `interface-assets`' (DEC-122 (3)). It has no inline event-handler attribute, no `javascript:` address and no script made from a string (`answer-envelope` R6). A test serves the page through the door and finds one script element, loading the shell's versioned script, and no inline script.

**The session** (held by the shell, R32)
- **R3** On load the page reads the session record `SESSION_STORE_KEY` names (R32). With none, or one whose expiry has passed, it goes to `/` (the interface's `front`, R32) and draws nothing else. With one, it sends `op=whoami` (`control-plane` R18); an answer without a member session (`session` false or `member` empty) is treated as none. A `401` answer to any request clears the record and goes to `/`. The session token travels only in each request's `Authorization: Bearer` header: never in an address, a query, a body, a link drawn or the browser's history (`admission` R20). A test drives every screen with a sentinel token and finds it in each request's header and nowhere else.
- **R4** The masthead's member initial opens a menu with "Sign out": it sends `op=signout`, then clears the session record and goes to `/`, whatever the answer.

**Words** (DEC-179)
- **R5** Every member-facing string the interface draws is a word read by key: a key of `setup-words`' `WORD_ROWS` (its R1), or a key of a module's own `SCREEN_WORDS` (frozen `[key, en, protected]` rows; a screen's keys `screen.<id>.<part>`, the shell's own `shell.<part>`, each with `{placeholders}`; DEC-179 (5)), never text written into a render function. After `whoami`, the shell reads `op=interfacewords` (`instance-setup` R74: the member's language, the group's shown translation, else the English); a key it does not answer, or a read that fails, is drawn in the English of `WORD_ROWS` or `SCREEN_WORDS`. `w(key, fills)` fills each `{name}` with the screen's data, HTML-escaped. A key of `WORD_ROWS` whose English names the group's Civicsmith bare (DEC-149) or is untrue on an arm a screen draws it for is not drawn from `WORD_ROWS`: the module that draws it holds its own row under the same key in its `SCREEN_WORDS`, in DEC-149's form and true on every arm, until a later `WORD_ROWS` carries a conformed word; in T46 these are `mark.gap.refused.means`, `mark.origin.search.means`, `ai.refused.limit.unjudged`, `queue.step-cost-shared.detail`, `act.memberlanguageset.does`, `act.groupkeyremove.does`, `act.owed_subscriptionsignin.does`, `act.pagetranscribe.does` (each names Civicsmith bare) and `handle.fixed` (untrue under DEC-197: every handle is fixed, published case or not). A test renders every screen in every state and finds each drawn text node equal to a word's text, filled, or to the record's own data (names, titles, quotes, dates, counts); a key no list holds fails it. (fix round 4, C59; K4472) A string the kit's `w` itself returned, handed back to a word as a fill, is inserted as it is; any other string is escaped once.
- **R6** Dates are drawn by `date.daymonth` and `date.daymonthyear` with `date.month.*` (DEC-191, DEC-192); no date is drawn in ISO form. (T51; DEC-333) The keys now give the American order (`date.daymonthyear` is "{month} {day}, {year}"); the code is unchanged. A test that copies a drawn date takes it from the key (`word("date.daymonthyear", …)` filled with `date.month.*`), never from a literal in either order.

**The frame and the path** (DEC-139 (1), DEC-154, DEC-155)

At the phone width the rail gives way to the five tabs Home, Queue, Add, Find, More (`tab.more.*`) and the dock to a sheet above them. A place whose screens are not yet built (People) is shown and opens a screen saying, in its words, that it comes later. (T51 fix round 2; K4339) The frame's own queue read asks `limit` 200 (C66). (fix round 4, P9; K4472; replaces K4339's `limit` 200 sentence) The frame sends its `queue` read with `count: true` once per load, in the background (queue R93), only when the screen reads no whole open list (`queue` with at most `limit` and `sort`), or that list was cut, refused or unanswered; where it is read whole, the number drawn is the sum of its three kinds (R93, R96; T51 fix round 5, E12, K4537); the three kinds in the masthead's explanation come from an open list a screen reads that is not cut by its limit; where none is read no kind is named and the explanation is not drawn. (T51 fix round 6, G12b; K4579; amends R7) The group's name may be drawn from the tab's kept read of `groupidentity` (R124).
- **R8** Every screen opens its main area with its path, at the same place: from its rail place to the screen's own name, last, marked as the current page, each earlier step a link; the heading below names the thing shown (a question's words, a document's title). Each screen's path is `docs/development/ux-substrate/screens/mock-shell.js`' `PATH` for its id at `3f40899950` (members: Settings › Members; held: Add › Held captures; document: Projects › <project> › Document), a project's step its title as read.
- **R9** The router maps `/app` to `home` and `/app/<screen>[/<subject>]` to that screen with that subject id, keeps the browser's history (back and forward redraw the screen), and answers an unknown screen, or a subject the read does not find, with the screen's "Nothing here" state (`state.empty`, R10), never a blank page. `/app/review` maps to `review-outside` (`screens-publish` R17; K3137, T47). (T51 fix round 2, C24; K4317) An address `/app/<place>` of a place that holds a built screen (`PLACE_SCREENS`) is rewritten to that screen's address; "comes later" is drawn only for a place with no built screen.
- **R25** *(retired (K3153): replaced by R37)* (Bob's K2893: Home) The Settings place offers "Group settings", a link to the setup page's panel (`/`), where the settings sections not yet redrawn are served (who the group is, places and offices, security tools, translations, recovery codes); the setup page's own link back to `/app` is `setup-page` R32's.
- **R26** (N673; DEC-155) The rail's width is the member's on each device: 184 px by default, from 64 to 320 px, set by dragging its edge or by the keyboard, kept on the device (the browser's storage) and never sent in any request or written to the record; at the phone width the tabs are unchanged by it. A storage that cannot be read or written leaves the default.

**Reads and their states** (DEC-98)
- **R10** Every read is drawn in one of four states: still loading (`state.loading`), empty (`state.empty`, or the screen's own empty sentence), could not read (`state.failed` with the refusal's words as `{reason}`, R13), or its data. A read that failed is never drawn as empty, and an empty one never as failed. A test answers each read of each screen in turn as pending, empty, refused and failed (no answer), and finds the four states drawn.

**Acts: weight, friction and the gate** (DEC-82, DEC-87, DEC-143, DEC-181, DEC-122 (1))
- **R11** Every act is a button labelled `act.<op>.label.<screen>` (or the registry's label's key where the screen has one), carrying its weight's pips and name (`weight.<w>.name`): the weight read from `op-grades`' `RUNGS` (`attested` drawn as `weight.signed`), an op whose `RUNG_ABSENT` ground is `undetermined`, or that neither names, drawn as reasoned (DEC-87: an undetermined rung is treated as reasoned). An op in `RUNG_ABSENT` under another ground (`substrate`, `credential`, `caller-owned`, `observational`: not an act on the record, `op-grades` R2) carries no weight mark and runs on press, any confirmation its owner requires drawn by its screen (K3002); so does a read (an op `OPS` declares `mutating: false`), whatever the tables hold (K3011). Friction follows the weight: reversible acts run on press; reasoned acts open a reason field in place and send only with a reason, except that an act whose screen names a `reasonField` sends the member's own words in that field as its reason and asks no second one (DEC-88: an act's own authored words serve as its reason); terminal and signed acts open a dialog stating what the act does (`act.<op>.does`) and who signs, and send only on its confirm. An act that leaves the group carries `mark.outward.means`. At the phone width a signed or irreversible act is drawn with what it does and a sentence saying where to finish it, and is not sent (DEC-181). No T46 screen offers an irreversible act. (T51 fix round 2, C76; K4317) An act drawn with the Reasoned mark is one the shell asks a reason for (`markAsks`); no other act draws it; a read draws no mark.
- **R12** An act is drawn only when the session may do it: `NEEDS[op]` is `null` or among `whoami`'s `capabilities`; the op is in `SESSION_OPS.member` (or `SESSION_OPS.admin` for the founder's session), or, for a read (`OPS[op].mutating` false; `SESSION_OPS` gates mutating ops alone, as the door does), the session's class is among `OPS[op].classes`; and, for an act its owner refuses to a member who does not administer (`membership`'s administrator acts, `credentials`' group-key acts, `aikeepaway`), `whoami`'s `administer` is `true`. An act not drawn is absent, never greyed (DEC-139 (7)). Before `whoami` answers, no act is drawn. `ADMIN_ACTS` is `wizard-scripts`' (its R51), which names `scanmirror` and `officeconfirm` among the others (fix round 3; K4380).

**Refusals**
- **R13** A refusal (`ok: false` at the top level or in `result`, or an HTTP error) is drawn beside the act or read it answers, never in place of the screen: the word `refusal.<code>` (or a screen's own key for that code) when one is held; else the answer's `translation` (`answer-envelope` R2); else `state.failed` with the code. A form keeps what the member typed; nothing on the screen changes but the refusal. A test drives every act of every screen with a refusal of each kind and finds the words drawn and the form kept. (T51 fix round 2, C11; K4317) A refusal drawn beside an act is drawn again by every redraw, until the act is pressed again, something else is drawn in its slot, or the screen is left.

**Explanations** (DEC-159 to DEC-163, DEC-175, DEC-177)
- **R14** Every mark, name and reference explains itself (level 1, marks and names); every screen heading, section heading, rail place, tab and act explains itself at level 2 (guidance: `screen.<id>.purpose`, `rail.<k>.holds`, `act.<op>.does`). An explanation opens after the pointer rests 0.5 s (level 1, and level 2 at "Explain promptly") or 1.5 s (level 2 at "On a longer pause"), at once on keyboard focus or a tap; stays while the pointer is on the element or the explanation; closes 0.5 s after it leaves both, or on Escape; one at a time; announced as the element's description. Nothing is hidden at either level.
- **R15** No explaining element sits inside another (DEC-177 (1)): a control or a mark with no label of its own absorbs those inside it, said after its own; a title naming a particular thing explains that thing first. A test renders every screen in every state, at both widths, and finds no element carrying an explanation inside another that carries one.
- **R16** Every item the record holds that a screen names (a document, a passage, a question, a project, a member, a capture) is a link opening its screen where one is built, and shows a card on hover or focus with what it is and the facts the screen's read answered for it (DEC-160 (1)–(3)); an item whose screen is not yet built carries its card only.
- **R17** The explanation level is the member's: the masthead control shows the current value (`level.prompt.name`, `level.pause.name`) and switches it in one click, as do Alt+Shift+I and the account screen (`screens-settings`). It is sent as `op=infolevelset` and read with `op=infolevel` (`instance-setup` R79); while either does not answer, the level is kept on the device, default "Explain promptly". A new member starts at "Explain promptly"; after their first month the shell asks once whether to keep it (DEC-162 (2)), the answer recorded through the same op.
- **R18** Appearance is "Follow my device", "Light" or "Dark", kept on the device; print is always light (DEC-122 (2), DEC-138 (6)).

**Rows, picks and the hold strip** (DEC-176; canon §S)
- **R19** A table of rows offers each row's acts in a panel opened beneath it (by its name or the keyboard), never elsewhere on the screen; ticking rows brings the hold strip with its count, the acts that apply to every picked row, and "Unpick all"; sorting keeps each open panel with its row; at the phone width each row reads as a card with every value labelled.

**The screen contract**
- **R21** A screen module exports `SCREENS`: per screen `{id, reads, render, acts, words}`. `id` is a `SCREEN_REGISTRY` screen id. Each act names one op; every op a screen's acts name is in `OPS`, and is the op the registry lists for that screen or one of the three re-points `draft-T46-interface.md` §3 names (`capture` → `captureupload`; `connect`'s owed sign-in → `subscriptionsignin`, its disconnect also `subscriptiondisconnect`; `answers`' "Ask" → `ask`), or `owed:infolevelset`'s op `infolevelset`. `interfacePage` throws, naming the screen, for a screen whose `id` is not in `SCREEN_REGISTRY` or whose act names an op `OPS` does not hold, so a broken screen is never served.

The shell opens no address itself: a screen draws an outside address as a link with `target="_blank" rel="noopener noreferrer"`. *(T51, K4254: an act may carry `failed(view, answer, cs)`, called when its request is refused or unanswered, before the refusal is drawn beside the act.
