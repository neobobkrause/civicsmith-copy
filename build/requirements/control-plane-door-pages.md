## Public

- **R75** (N897 (1); DEC-122 (3); N559; fix round 3, C15, P2.4; K4353, K4356) `GET /app` and `GET /app/<path>` (any path below it) answer `interface-shell`'s page (`interfacePage` over the four screen modules' `SCREENS`), `text/html`, `cache-control: no-store`, through the same namespace and address gates as `/` (R1; `admission` R1, R20), under `answer-envelope` R6's page policy, which names the shell's script by its hash (`interface-shell` R1) in place of a nonce per response. The shell's script, at its address that carries the release version (`VERSION`, R1), is answered `text/javascript` with `cache-control: public, max-age=31536000, immutable`: a release's script is not sent again to a caller that holds it, and a new release has a new address; the page itself keeps `no-store`. `GET /app/assets/<name>` answers `interface-assets`' file of that name (`ASSET_FILES`, its R1) with its content type (`text/css`, `font/woff2`, `image/svg+xml`, `text/plain` for a licence), a face's bytes decoded from base64, and a `cache-control` that lets the browser keep it while the plane's version is unchanged; any other name is answered 404. No credential is read on either route: the page holds no secret, and every read is an op under the member's session. The end-to-end suite runs here: over Miniflare and the real plane (`src/plane/index.mjs`), `GET /app`, the shell's script and `/app/assets/*` served with the policy and the script's hash; a member signed in through the interface's own sign-in (`login`, the real plane's handler); then `home`, `capture` with an upload, `held` and `release`, each read back through the real ops.

- **R116** (fix round 2, C15; K4317; amends R66) **`interfacewords` is cached for the release and compressed.** The answer of `op=interfacewords` carries a long-lived cache header whose validity is keyed by the release version (`VERSION`, R1): the same release's words are not sent again to a caller that holds them, and a new release's words are fetched afresh; the body is sent compressed to a caller that accepts a compressed body, and is the same words either way. The header does not change who may read the words or the gates of R66. (The key, the validator and the `vary` are R127's, which supersedes CONTROL-PLANE #43's as-built form: a `v` of the release alone, a weak `etag` of the version and digest, and `vary: Authorization, Accept-Encoding`. What stays: every answer that is the words is gzip-compressed for a caller that accepts gzip, whatever its `v`; an answer that is a refusal and every other op are left as they came. `interfacewords` is declared by `translations` (its R21): `fields.accepts` `language` and `v`, nothing required, `viewer` the door's stamp.) Test: two requests of one release, the second sending the first's validator, are answered as unchanged (or served from cache by the header's lifetime); a request after `VERSION` changes is answered in full; a request accepting compression is answered compressed and decompresses to the same words. Control: the page of `GET /app` keeps `cache-control: no-store` (R75).

- **R122** (fix round 4, P9; K4429) **The page's bootstrap is read once per load.** The shell's page asks `op=bootstrap` once per page load and hands its answer to the frame and the screen; no screen asks it again in the same load. Test: loading Home, Queue and Project each sends exactly one `bootstrap`; control: a new page load sends one again. (fix round 4, K4472) The shell's side is met by interface-shell (a screen's `{op: "bootstrap"}` read is answered from the page's one answer; a read after a successful act, a sign-in or a sign-out asks again); the id stays marked until control-plane's `t51-bootstrap` whole-path test is green.

- **R127** (fix round 8, G114; K4811 (7), K4814 (1), K4817, K4822; K4853; amends R116) **The words are fetched once per browser, release, language and adoptions.** The words' `v` is `<release>~<language>~<words_version>` (the three joined by `~`, in that order; `words_version` is `translations` R20's). A viewer with no language (the owner answers `result.language: null`) has the EMPTY part: `v` is `<release>~~<words_version>`, kept like any other; no other `v` (`<release>~es~<words_version>` included) is a no-language answer's key, and `<release>~~<words_version>` is no key for an answer in a language. The door learns the language and the stamp from the owner's `interfacewords` answer (`result.language`, `result.words_version`, `translations` R19, R20) and compares the three parts with `VERSION` and that answer. Exactly that `v` is answered `cache-control: private, max-age=31536000, immutable` with a weak `etag` of the key and `vary: Accept-Encoding` only, never `Authorization`, so a second sign-in in the same browser is served from its cache or a 304 on a held validator; any other `v`, the release alone included, or none, is answered `private, no-cache`. Every answer that is the words is gzip-compressed for a caller that accepts gzip, whatever its `v`. R66's session gate stays. The door reads a bounded head (8 KiB) of the answer and streams the rest; it does not read the whole body of this op's answer to tally it unless it is a refusal (known by its status and header; a 200 `{ok: false}` without the header is still read). Test: two sign-ins in one browser context, the second answered from cache or 304; two languages each get their own words; an adoption is seen at the next load; the whole-body reads counted; a viewer with no language is kept under `<release>~~<words_version>` (a year, a validator, a 304) and any other `v` for that answer is `private, no-cache` (`r8-words-cache.test.mjs`, `r8-words-door.test.mjs`, `r9-words-no-language.test.mjs`).

## Private

- **R126** (T51, fix round 6, G30; B-21; K4428, K4609; `interface-shell` R126) **The front page names its work.** Every page the door draws (`GET /`, `/app` and below, and the unknown-address page, R104) writes one structured log line `{event: "control-plane.page", scripts, hashes, checks, ms}`: the counts of scripts composed, hashes taken and screen and guide checks run in this isolate (`interface-shell`'s `pageWork()`), and `ms` the isolate's clock; counts, not CPU times (R-CLOCK). The line carries no credential, member, address or name; no other route logs it; the page's answer is unchanged. Test: `t51-page-log.test.mjs`; control: a route that is not a page logs none.
