# instance-reports — requirements

**Status** · New 4 Nov 2026: split from `instance-setup` for size (its requirement lines alone are over the 70,000-byte cap; the split proposed by `instance-setup`'s job, attempt 1, in `docs/requirements-notes/instance-setup.md` on `job/instance-setup`), accepted by the coordinator (BOB) 4 Nov 2026; K617, K624. A new module, layer 11, directly after `instance-updates`, split by copy with no `from`. R1–R21 are `instance-setup`'s R17, R18, R19, R33, R34, R35, R36, R37, R38, R39, R40, R41, R42, R80, R81, R82, R95, R102, R103, R104, R105, copied verbatim with their marks and renumbered in the order of their old ids, meaning unchanged; each line says "moved from instance-setup:R<n>". `instance-setup`'s own restarted job removes and retires the moved lines there, naming their new ids, and never reuses them. A bare `R<n>` inside a moved line that names no module is a `instance-setup` id. The code this module owns today is `bio-plane/src/livefire.mjs` and the bootstrap, selftest and probe-measure code in `bio-plane/src/setup.mjs` and `setup-fleet.mjs`: it moves here only once `instance-setup`'s job has retired the lines; until then this module's job implements here and leaves `instance-setup`'s code to its job.

## Public

### Purpose

The instance's bootstrap, selftest and livefire reports, and the runtime and CPU probe measures. R95 reads `instance-setup`'s display name and `instance-updates`' `running_releases`.

### Provides

- **R1** (moved from instance-setup:R17) `op=bootstrap` answers `service`, `version` (this isolate's `VERSION`, `0.0.0` when unset), `bootstrapConfigured` (a live `ADMIN_TOKEN`: set, and not a published value), `credentials`' `bootstrapState` (its R2; K3004) and `storeVersion` read from the record store's own environment, never the isolate's; with `members=1` it adds `memberVersions`, for each member in `FLEET_BINDINGS` its own `/version` asked through the binding within 4 seconds: `SERVING` with its version, `UNBOUND`, `SILENT` or `MISNAMED` (another worker answered).
  (T46; N897 (4); `build/plan/draft-T46-trial.md` §3.2; `agent-worker` R30) `agent-runner`, which the plane does not bind, is answered in `memberVersions` from agent-worker's `/version` `runner`: `SERVING` with agent-worker's version when it answers `runner: true`, `UNBOUND` when `runner: false`, and agent-worker's own state (`UNBOUND`, `SILENT` or `MISNAMED`) otherwise, never `UNBOUND` merely because the plane holds no binding to it. Control: an agent-worker answering `runner: false` reports `agent-runner` `UNBOUND`, and `runner: true` `SERVING`.
  (`instance-setup` F2; journey-check, 7 Nov; `agent-worker` R30 as T53 amends it) agent-worker's `/version` no longer says `runner`: an agent-worker that served without it answers `agent-runner` as its part, `SERVING` via agent-worker with its version and its `ai_path_ready` when that is a boolean, never `SILENT` for the missing key; `runner: true` and `runner: false` read as above. Control: no agent-worker answers `UNBOUND`.
- **R2** (moved from instance-setup:R18) `op=selftest` answers `bindings` (`STORE`; `CAPTURES` and `PUBLISHED` each `true` or `"not configured"`; each token binding live or not, `DAEMON_TOKEN` `"not configured"` when unset), `r2Configured`, the store's stats, and an R2 round trip under the scratch prefix; `ok` is false when exactly one bucket is bound, when the store does not answer, or when the round trip fails. (T36) `MEMBER_TOKEN` is no binding: `op=selftest` neither reads, reports nor requires it, and `ok` and `bindingsAllPresent` rest on `STORE`, `ADMIN_TOKEN` and `PROBE_TOKEN` (with R18's buckets and round trip as before).
- **R3** (moved from instance-setup:R19) `livefire` runs only against the namespace it is handed, writes only a nonce-named canary bundle there and R2 keys under `scratch/`, and asserts by name: creation, `EXISTS`, a revision on the right base, `row_version`, `CAS_STALE` on a stale and on a garbage base, the winning revision live, the superseded one in history, the promotion records and manifest projected, `OVERSIZE_INLINE`, the nonce read back, `allocid` gapless, the lease base and a second actor denied, no configured token a published value or under 16 characters, and R2 (both buckets or neither; round trip, range read and sized throughput when bound). It answers `ok: true` whenever it answers, `verdict` `pass` exactly when every assertion and R2 passed, and `failing` naming every failed assertion (never empty on `fail`). (T36) `livefire`'s token assertions run over the configured `ADMIN_TOKEN`, `PROBE_TOKEN` and `DAEMON_TOKEN`; a run that acts as a member does so under a member's session or an `aik-` agent credential (`credentials`), never a shared member bearer.
- **R4** (moved from instance-setup:R33) `recordRuntimeObservation` requires a non-empty `metric` and a finite number `ms`, else it answers `{recorded: false}` and writes nothing. The first observation of a metric records it as both peak and last, with `samples` 1; each later one sets last and its instant, adds one to `samples` and the value to the running total, and replaces the peak (value, instant, `detail`) only when strictly greater. It answers `{metric, peak_ms, last_ms, samples, new_peak}`; `at` defaults to now, to the second. Never throws.
- **R5** (moved from instance-setup:R34) `runtimeObservations()` answers every metric in name order with its peak, last, samples, total and `mean_ms` (total over samples), each metric with the unit it was recorded in; a count of work is never described as a time.
- **R6** (moved from instance-setup:R35) `recordCpuProbeStep` records one completed probe step: its number, its elapsed time from its run's start, its iterations and the instant (`at`, default now to the second), and answers `{step, elapsed_ms}`. Never throws for a well-formed call.
- **R7** (moved from instance-setup:R36) `cpuProbeState()` answers `{steps, highest_completed, elapsed_at_highest_ms, rows, note}`, `rows` in step order; with no step recorded, `highest_completed` and `elapsed_at_highest_ms` are 0 and the note says nothing is known about the ceiling by measurement; otherwise the note says the ceiling lies above `elapsed_at_highest_ms`. Writes nothing.
- **R8** (moved from instance-setup:R37) `op=runtime` answers `{ok: true, measured, cpu_probe, subrequests, asymmetry}`: R34's answer, R36's answer, `capture.captureLimit("subrequests")` (capture R23), and a sentence stating that the subrequest ceiling is known by having been refused while the CPU ceiling, which ends the isolate, is found by `op=cpuprobe`. When any of the three reads does not answer, the op answers the store-silence refusal, never `ok: true`.
- **R9** (moved from instance-setup:R38) `op=cpuprobe` reads R36 first; when the store does not answer it answers the store-silence refusal and burns nothing. It runs `runtime-limits.cpuProbe` with `iterations` per step (at least 100,000; 2,000,000 when absent or not a number) and `budget_ms` (at least 50; 20,000 when absent or not a number), each run starting at step 0 under its own run id (R40), and records each completed step through R35 before the next step begins. It answers `{ok: true, run, state, note}`: the probe's result, R36 read after the run (store silence answers the store-silence refusal), and a note saying that a run which returned bounds the ceiling from below.
- **R10** (moved from instance-setup:R39) A checkpoint the store does not confirm ends the probe: no further step is burned, and the op answers that the trail is incomplete, naming the last step the store confirmed.
- **R11** (moved from instance-setup:R40) Each probe run's trail is kept apart from every other run's: R36 answers, for each run, its steps with their elapsed times from that run's own start, and the ceiling is bracketed within the run that was cut off (its last completed step and the next). A run never continues an earlier run's step numbering as if the two were one isolate's work.
- **R12** (moved from instance-setup:R41) The runtime observations and the probe trail (R33–R40) are measurements of the runtime, not of the corpus: `purge` never clears them, in either form (declared to record-core exempt, record-core R21, R23).
- **R13** (moved from instance-setup:R42) At start this module registers with `capture` (its R55) a listener that records each walk's compute measurement through R33 (`metric` `capture_work_bytes`, the value as `ms` until R34's unit is recorded, the detail as given). *(met in substance: `legacy-store` registers this listener on capture's R55 today, and this module takes the registration at its extraction; the store route `recordruntime` is left with no product caller and goes with it)*
- **R14** (moved from instance-setup:R80) (T46; N897 (2); K2816 (2); trial §1.2; `ai-runs` R78) `op=bootstrap` also answers `test_instance`, `true` exactly when `ai-runs.testInstance()` answers `true`, else `false` (a read that throws answers `false`). It names no value of `CIVICSMITH_TEST_INSTANCE` or `INSTANCE_NAME` beyond what `bootstrap` already answers, and no op, body, query or table sets it. The interface reads it. Control: with the environment pair unequal or absent, `test_instance: false`.
- **R15** (moved from instance-setup:R81) (T46; N897 (4); trial §3.2) `op=bootstrap` also answers `parts`: `[{part: "signin", present}, {part: "scanner", present}, {part: "safe_view", present}]`, each `present` `true`, `false` or `null` (could not be read). `signin` follows R17's `agent-runner` answer (`SERVING` `true`, `UNBOUND` `false`, otherwise `null`); `scanner` and `safe_view` follow `FILE_SCANNER`'s answer the same way. It names no reason beyond the part. Each screen that offers a part reads it (the `connect` screen's sign-in, the security screen). Control: a fleet with no `agent-runner` and no `FILE_SCANNER` answers all three `false`; a `FILE_SCANNER` that does not answer in time answers `scanner: null`.
- **R16** (moved from instance-setup:R82) (T47; N989, N982; K3027; amends R81; `membership` R132) `op=bootstrap` answers the parts as three flat scalar keys, `part_signin`, `part_scanner` and `part_safe_view`, each `true`, `false` or `null` (could not be read), and holds no `parts` key and no nested object or array, so `membership` R132's pre-auth invariants hold whole. `part_signin` follows R17's `agent-runner` answer as R81 states. `part_scanner` and `part_safe_view` are one part today: `file-scanner` both scans and renders the safe view, and its `/version` names no separate renderer, so both follow `FILE_SCANNER`'s answer as R81 states and are always answered alike; a separate renderer, if one is built, is given its own answer by a later requirement. Each screen and page that offers a part reads its key (`setup-page` R34, the `connect` screen, the security screen). Controls: the pre-auth answer's key set is exactly `membership` R132's; a fleet with no `FILE_SCANNER` answers `part_scanner: false` and `part_safe_view: false`; one that does not answer in time answers both `null`.
- **R17** (moved from instance-setup:R95) (T51; N1239; K3777; DEC-282; BOB's ruling on the disclosure (the seven facts to a credentialed caller only); `installer` R63; amends R17, R81, R82) **`op=bootstrap` states what is already here, to a credentialed caller only.** Beside R17's, R80's and R82's keys, an `op=bootstrap` request that presents a credential the door admits as the deployer's or an administrator's (an `admin`-class token or an administrator's signed-in session) is answered, as flat scalars at the top level (no nested object or array), the wire names the installer reads (`newgroup/src/account.mjs`' `FACT_KEYS`):
  - `team_name`: the display name as its members read it (R6, R10: the name `groupIdentityPublic` states, only while a slug is recorded), else `null`;
  - `installed_at`: the instant the running release was first seen (R88 records it in `running_releases`; R89's `updateNotice` answers it as `running.installed_at`), else `null`;
  - `last_used_at`: the instant of the newest activity of any session held (`credentials` R65: activity is any request not marked background; `sessions.last_active`), else `null` when none is held or it cannot be read;
  - `count_projects`, `count_documents`, `count_published` (published case editions) and `count_members` (active members): non-negative integers, each the copy's own figure taken whole, not through a viewer's sight (the installer is told the size of what removal would delete), else `null`.
  A fact this release cannot read at this moment is stated `null`, never omitted and never `0`; none is guessed. No value names a member, handle or role, no value is a list, and no other key changes. **Without a credential none of the seven keys is in the answer**: the pre-auth answer is exactly the key set `membership` R132 fixes (R132 is not changed: the answer a stranger gets holds none of the seven, so R132's rules (1) to (4) hold of it as they do today), so a stranger learns nothing of the team's name, size or last use, and the installer, which presents no credential to a copy it did not make, draws each fact "not known" and its own counts (installer R63) stand. A copy that withholds them cannot be told by the installer from an older release (R132 admits no new key to say so); installer R63 words that reason accordingly (BOB carries it to `installer`). **Where the change is made:** `bootstrap` is public (`classes: null`) and the door's `publicOp` hands `bootstrapOp` only the fingerprint; the caller's credential class reaches `bootstrapReport` through `plane`'s door (BOB's to place with `control-plane`), and the seven are read by the store only for such a caller.
