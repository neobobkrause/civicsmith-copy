## Suggestions (the requirement lines R112–R116, R126, R127 stayed in the requirements file)

- **How screen code reaches the browser** (`draft-T46-interface.md` §1.3, §7 T1, BOB's): each screen module exports self-contained browser functions, each referring only to its parameters and the kit object `cs` handed in, never to a module-scope import; the shell composes the page's one script from their `toString()`, as the old setup page embedded `deriveInquiryTitle`. The functions run unchanged in node for tests and in the browser.
- **The kit** `cs` handed to screens holds `read`, `act`, `w`, `state`, `row`, `ref`, `mark`, `grade`, `due`, `sheet`, `sec`, `field`, `choice`, `checks` (the mockups' `mock-kit.js` names). Screens draw HTML strings; acts are bound by delegation on `data-act` attributes, so no inline handler exists.
- **Tests** (§4, §7 T2): the served page through a DOM stand-in with a scripted `fetch`, as the deleted `setup-page`'s `fixture.mjs` did; one small shared stand-in owned by this module's tests and imported by the screen modules' tests (no new dependency). R14's timings with a fake clock.
- **Routes** are path routes with history (§7 T6), so a link survives a reload and can be shared inside the group.
- The page may pass `store=scratch` to each op for live verification. A failed `interfacewords` read is retried once on the next screen change.
- The words not adopted (R5) and the screens' own sentences are a HANDOFF to the design stream in BOB's channel act (plan T46, "BOB's acts").
## Split proposal (job interface-shell, attempt 1, 4 Nov 2026), for BOB

**Why moving text out can't reach the cap.** The file was 140,326 bytes against a cap of 70,000. After the move it is 131,579 bytes. The 150 requirement blocks (each **R** line with the indented lines beneath it, all requirement text) come to **129,399 bytes** on their own. Even R1–R89 together are 72,979 bytes, so a split into two still leaves one half over the cap.

**Proposed split into three, by tranche, renumbered and verbatim, in the way op-declarations was split:**

- `interface-shell` keeps **R1–R51** (T46, T47 and its L11 fold): 37,459 bytes of blocks.
- A new module (the name is BOB's to choose, for example `interface-shell-t48`) takes **R52–R89** (T48–T50): 35,520 bytes.
- A new module (for example `interface-shell-t51`) takes **R90–R151** (T51, its fix rounds, T53, and the R112–R116, R126 and R127 that were filed under Suggestions): 56,420 bytes, with 16 unmet T53 marks (R136–R151).

The code is one browser script (`browser.mjs`, 2,944 lines) with `index.mjs`, so the new modules would hold requirements and tests first, and their code would move only where a seam exists (the kit `cs`, the frame's reads). That makes the split a requirements-and-tests move. BOB can also choose to let this file stay over the cap.
