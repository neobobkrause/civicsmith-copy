## 2. Gaps between the design of record and the code

The design of record is DB `investigation-design.html`. Canon `BIO_Investigation_v0_1.md` restates it.

1. **No screen reaches the investigation construct. [ux]**
   - No file under `bio-plane/src/screens-*`, `interface-shell` or `wizard-scripts` sends any `investigation` or `steps` op. This holds for `stepcreate`, `stepend`, `stepslike`, `milestoneset`, `reportdraft`, `interviewkeep`, `narrativeclaim`, `planaccept`, `projectstanding`, `quietstate` and `questionfollow`. The only exception is `projectclose`, which 2 screen files send.
   - Outside the modules, these ops appear only in owner-ops, op-declarations, op-grades, the release bundle and one walk script (`build/plan/walk-T51-final/scripts/09-question.test.mjs` for `stepcreate`).
   - So steps, milestones, status reports, the intake interview, narrative claims, "where the evidence stands" and following a question are built, and reachable as ops, but **no member can use them through the product UI**.
   - This repeats the D42 study's finding of 10-09: "most built ops have no screen" (DB HANDOFF.md:82).
2. **N1272's investigation acts are not served as ops.**
   - `markForInterpretation`, `proposeParts`, `acceptProposals` and `interpretedFor` (investigation R26–R31) have no entry in `store-assembly/owner-ops.mjs` or `op-declarations` (grep for `markforinterpretation` finds nothing).
   - They are in-process only. Their screens are **[ux]** (K5495's interpreted-part mark).
3. **Proposals can never be offered yet.**
   - `PROPOSALS_MEASURED = {}` (`investigation/index.mjs:57`). Per R29, every file kind answers `unavailable: not_measured` until the M-N1272 measure runs (K5537).
4. **The AI test bar cannot be passed.**
   - `run-rules/test-set.mjs`: `CIVICSMITH_TEST_SET.matters = []`. Its own header says no AI part is deployable under R19 "until a later version adds them". People must write the matters (D11, D14).
   - `question-explorer.gate` (`index.mjs:301-322`) shuts without a passed bar. It has an `untested`-label exception path (`:309`), and whether that exception now opens exploring is not settled here.
   - Effect: exploring, planning (`enquire`) and other AI parts are gated off. That matches the design's rule ("not offered until it passes its test investigations"), but nothing has been seeded to pass it.
5. **Civicsmith's reading-guide library is empty.**
   - `reading-guides/library.mjs:57` `CIVICSMITH_GUIDES = freezeLibrary([])`.
   - The design calls for "a library shipped to every group … each guide only after measured use". The mechanism is built; there is no content.
6. **The front door is not D52's six routes. [mostly ux]**
   - D52 rules one door, "What happened?", leading to six places: a new project; an existing question or project; a lead with an optional watch; a step for understanding; an action; "not Civicsmith's".
   - The code's `FRONT_DOORS` (`wizard-scripts/front-doors.mjs:10-13`) are subject doors (`problem`, `person`, `money` …) that offer wizard scripts, plus a sixth "elsewhere" door (`ELSEWHERE_DOOR`, screens-daily R14). `wizard-scripts` R27 says the doors are N821's to fill.
   - Routing a first message to "a step for understanding", "a lead with watch" or "an existing question" is not visible as a front-door outcome. Worth a closer check.
7. **The member-facing names are still unruled.** D23: what a member sees for a step, a milestone and a status report, and the name that tells the investigation's plan from the action plan. This is canon Incomplete §3, owed with the UX stream **[ux]**. The code uses internal words (`steps`, `INTERVIEW_WORK`, `FIND_WORK_PREFIX` "Find the record: ").
8. **Canon may be stale on regrade.**
   - Canon `BIO_Investigation_v0_1.md` Incomplete §11 says regrade "is not built".
   - The code has `case-checker` lens checking (`check.mjs:4-11`, `lens.mjs`, `account.mjs:212, 331`) and `bias_applied` on legs (inquiry R61, basis-versions).
   - Unresolved: whether the reader re-check (D59) is complete, which would make the canon line stale.
9. **The ledger record is incomplete.** `steps`, `hypotheses` and `observation-log`, the core of the step model and of looks, have no `process/ledger/*.json`. Their build state is not recorded by the process the way `investigation` (COMPLETE) is.
10. **Where the code is faithful to the design, no gap was found in:**
    - per-question outcomes, machine never judging (`OUTCOMES` with `undetermined` default, steps R5)
    - no nesting (steps R21)
    - no purpose or method field (R1)
    - hidden projects never named (R3), and `leg-earning.projectsShownOn`
    - cost notice only when no sharing project is hidden (R14)
    - nothing measures a member (steps R20, investigation R8)
    - working material never published (R10, R19)
    - the objective is computed, not declared (`intent.progress`/`gaps`, `projectStanding`)
    - the bar never gates a leg (steps R27)
    - D54 administrator sight
    - D18 shared notes
    - D22 bearing note
    - D56 account check
    - D60 approval rule
    - D62 whole-case accept
    - D39 explore setting (`EXPLORE_VALUES`)

    These were checked at the level of names and headers, not line by line.

## 3. Does the build read `docs/development/investigation-design/`?

**No.**
- `process/config.json:33-36` lists it only as the `investigation` lane's folder, in `lanes`, with module `investigation-design`.
- No `generated` entry in `process/config.json` names it. The generated entries are words JSON under `docs/development/ux-substrate/`, `setup-words/rows.mjs`, the case-checker program and the dist bundles.
- No `.mjs`, `.js`, `.json`, `.sh`, `.py` or `.yml` file in the tree references the path, apart from config.json.
- The only build-side mention is prose: `build/requirements/steps.md:101` cites the design of record (`investigation-design.html`, K2417) as the source of the requirement text.
- The lane's folder is therefore free to change without breaking a build or a test. That is consistent with the standing rule: "A pull request that changes only files in its own lane's folder lands … without a test suite run" (CLAUDE.md).
