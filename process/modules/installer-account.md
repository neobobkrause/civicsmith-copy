# installer-account: requirements

Next number: 46

## Public

### Purpose

The installer's reach into a group's Cloudflare account: the patient call to the management API (`api.mjs`), the byte helpers (`bytes.mjs`), a copy's names, what the account holds, the lock and the mark (`account.mjs`), the plan, bucket, address and storage probes (`probes.mjs`) and the scopes a token lacks (`scopes.mjs`). Taken from `installer-steps` with its requirements and numbers.

### Provides

Numbers are `installer-steps`'s, kept when ARCH split it (22 Nov 2026); a bare R<n> not here is that number in `installer-steps`. Its tests run through `installer-steps`'s test world and barrel, so they are `installer-steps`'s until this module has a world of its own (code work for its job).

**The call to Cloudflare, and what the account holds**
- **R1** [met] (split from `installer` R66, R71, R19; F4, F6) `cfCall(session, path, init, base)`, and `cf(session, path, init)` which is the same bound to `CF_API`, make one call to the management API with the session's bearer and answer the reply's `result`. A reply that is not ok or states `success: false` throws an Error carrying the API's first message (else `HTTP <status>`), its `code` and `status`. A 401 throws `ApproveAgain` (`approveAgain: true`) and is never retried. A failure waiting can mend (429, 5xx, no answer) is retried with back-off, 2 s doubling to 30 s, until `WAIT_BOUND_MINUTES` (5) of nominal waiting have passed, each wait announced by `session.onWait(waited, bound)` before it, then thrown as `Lasting` (`lasting: true`, the cause's message, status and code); the waits are the delays asked for, never read from a clock. A POST is repeated only when `init.idem` marks it safe, or after a 429 (the platform said it did nothing). `special(e)` is true of an `approveAgain` or a `lasting` error and `approve(e)` of an `approveAgain` alone; `apiOf(session, account)(path, init)` is the call with `/accounts/<id>` in front; `patiently(fn, {onWait, minutes})` and `sleep` are the same wait for any other call. The token is read only where a request is made; `String(session)` is `[session]`, and no error or answer carries the token. Test: a 429 then a 200 completes after one announced wait; a 401 throws `approveAgain` after one request; a 503 for the whole bound throws `lasting` having announced each wait; a POST not marked `idem` answering 500 is not repeated, one answering 429 is; control: with every timer immediate the same waits are counted (no clock is read).
- **R2** [met] (split from `installer` R64) `namesFor(slug, scheme)` answers a frozen `{slug, scheme, captures, published, member(m), app(m, class, multi), role(r)}`. In the `slug` scheme: the buckets `bio-captures-<slug>` and `bio-published-<slug>`, a member's Worker `<member>-<slug>`, a container application `<member>-<slug>` (one class) or `<member>-<class lowercased>-<slug>` (several). In the `legacy` scheme: the fixed `bio-captures` and `bio-published`, the member's own name, and `<member>` or `<member>-<class lowercased>`. `role("captures")` is the captures bucket, any other role the published one. `schemeOf(bindings, slug)` reads a plane's `CAPTURES` r2 binding: `legacy` for `bio-captures`, `slug` for `bio-captures-<slug>`, `null` when it names neither or is absent. Pure; never throws. Test: both schemes for a one-class and a two-class member; `schemeOf` of each binding and of none. Control: two slugs share no name in the `slug` scheme.
- **R3** [met] (split from `installer` R62, R69, R70) `inventory(api, memberNames)` answers `{scripts, buckets, planes, orphans}`: `scripts` a Map of the Workers by name (with their migration tag where stated), `buckets` the names, `planes` one `{slug, scheme, bindings, finished}` for each Worker that holds the Durable Object class `Store` (`scheme` from R2's `schemeOf`, else `slug`; `finished` true for the `legacy` scheme and for a plane holding the binding `INSTALL_COMPLETE`, R6), and `orphans` `{legacy, slugged}`, the buckets and members no plane of that copy holds: the fixed names in `legacy`, the others in `slugged` (a Map from slug to names). A lookup that fails throws, and so does a plane whose settings cannot be read: an absence not established is not established. `allCopies(inv)` lists every copy, a plane and what it holds, or what is left of one without a plane (the fixed-name remains under the slug `bio-captures`). `freeName(slug, taken, validate)` answers the first `<slug>-<n>` (n from 2 to 99, within 40 characters) that is not taken and valid, else `null`. `listScripts`, `listBuckets`, `listNamespaces`, `listApps` answer lists (empty for a reply that is not one); `bindingsOf(api, name)` a script's bindings `{name, type, …}` or `null` when they cannot be read (unknown, never none). Test: a fake account with a finished copy, an unfinished one under its slug, one under the fixed names, and stray buckets: each in its place; a failing lookup throws; control: a secret's value is never read.
- **R4** [met] (split from `installer` R63) `readCopyFacts(address)` makes one `op=bootstrap` request, no credential, to the copy's address and answers, for each of `team`, `installed`, `used`, `release`, `projects`, `documents`, `published`, `members`, `{known: true, value}` when the flat wire field (`team_name`, `installed_at`, `last_used_at`, `version`, `count_projects`, `count_documents`, `count_published`, `count_members`) is a non-empty string or a non-negative integer, else `{known: false, why}`, `why` `silent` when there was no usable answer (no address, a network failure, not ok, not an object) and `older` when it answered a version but not this field. `countsViaApi(api, copy, memberNames, scripts, spaces, apps)` answers `{workers, containers, captured, published}`: the copy's Workers present, the container applications on their Durable Object namespaces, and the objects in each of its two buckets, `null` for a count that cannot be read. Never throws on a copy that is silent or refuses. Test: a stub copy answering name, release and counts; control: a silent one answers every fact unknown with `silent`, and one that answers a version but no counts, `older`.
- **R5** [met] (split from `installer` R65; DEC-282) `resourcesOf(api, copy, memberNames)` lists everything one copy holds as `{kind, name, id?}` in the order it is deleted: its container applications (those on its Workers' namespaces), its members' Workers, its plane, then its two buckets. `deleteResources(api, resources, done)` deletes in that order (a Worker with `?force=true`; a bucket emptied page by page, then deleted), calls `done(resource)` after each, and at the first refusal throws an Error carrying `remaining` (the names not yet deleted, the refused one first), `cause` and `status`; an `approveAgain` is rethrown unchanged. It deletes nothing that is not in the list. Test: a copy beside another: after the deletion the account holds none of the first's resources and all of the second's; a refused bucket names itself and what follows; control: `resourcesOf` alone deletes nothing.
- **R6** [met] (split from `installer` R69; F9, K3747) One run at a time, and the mark. The lock is the throwaway Worker `bio-install-lock` whose plain-text bindings `T` (the time it was last touched) and `ID` (the run's id) are its only content. `takeLock(api, lock, now)` answers false when that Worker exists and was touched within `LOCK_LIVE_MS` (3 minutes) by a run other than the one `lock.again` names (a revoked permission cannot drop its lock, and the run that continues it is not stopped by it), and otherwise touches it and answers true. `touchLock(api, id, now)` rewrites it; `dropLock(api)` deletes it and never throws (a lock goes stale by itself). `MARK` is `INSTALL_COMPLETE`, the name of the secret binding an install writes last. Test: a lock touched a moment ago stops a second run; one older than the bound does not; the continuing run is not stopped; control: `dropLock` on a refused delete throws nothing.

**The probes**
- **R7** [met] (split from `installer` R4, R6; DIST-3, DEC-42) `establishPlan(session, account)` finds the plan by provoking the platform, never by reading a plan field. It uploads the throwaway Worker `bio-plan-probe` (`PLAN_PROBE`) carrying `limits.cpu_ms`. Code 100328 answers `{plan: "free"}`; any other failure `{plan: "unknown", detail}` with the platform's message; an accepted upload is deleted at once (`?force=true`) and answers `{plan: "paid", leftover}`, `leftover` true when that deletion failed, which the caller says. Test: 100328 is free; a 500 is unknown with its message; an accepted upload answers paid and the probe is gone; a refused deletion answers paid with `leftover`. Control: no plan field of any reply is read.
- **R8** [met] (split from `installer` R5, R7) `scriptExists(session, account, name)` answers true when the script's settings answer, false only on a 404, and throws on any other failure: a lookup that fails is not a lookup that found nothing. `ensureBuckets(session, account, names)` creates the captures bucket and then the published one; "already exists" (any case) counts as created, and it answers the names that were already there; any other failure throws. Test: an existing bucket is named in the answer; a refused creation throws with the platform's message; a 500 on a lookup throws, a 404 is false.
- **R9** [met] (split from `installer` R14) `ensureSubdomain(session, account, slug)` reads the account's workers.dev prefix (a 404 is none). With none it registers `<slug>` and, only when that answer says the name is taken, exists or is unavailable, `<slug>-` and four lower-case alphanumerics; when both are taken it throws "no workers.dev prefix is set on this account and the names tried were taken", and any other error is thrown as it is. It then enables the script's address, and answers `{sub, registered}`, `registered` null when the account already had a prefix. Test: a prefix held is used; none is registered from the slug; the slug taken registers the suffixed name; both taken throws; control: a refused enabling throws.

**The keys that sign**
- **R43** [met] (fix round 9, K4937; G144) `storageEntitlement(session, account)` reads `GET /accounts/{id}/r2/buckets` and writes nothing: `{state: "on"}` on success; `{state: "not_entitled"}` on R2's not-entitled answer (code 10042, as measured on the rehearsal account, K4942); `{state: "permission"}` for want of scope; else `{state: "unknown", said}` with Cloudflare's message. `ensureBuckets` matches "already exists" by R2's code (10073 BucketConflict), not by words.
- **R44** [met] (fix round 9, K4937; G147; amends R9) `addressState(session, account, slug)` reads the prefix and, with none, proposes `<slug>` (never registers); `registerSubdomain(session, account, name)` registers exactly the name the founder chose and answers `{ok: true}` or `{ok: false, taken: true}` on Cloudflare's taken answer (its code as measured), else throws with Cloudflare's message; `ensureSubdomain` registers nothing itself (it enables the copy's address on the prefix the account holds). A taken prefix is Cloudflare's HTTP 403 with code 10031 (measured on the rehearsal account, K4970), answered `{ok:false, taken:true}`.
- **R45** [met] (fix round 9, K4937; G148) `missingScopes(granted, needed)` answers the scopes of `needed` absent from the token response's space-separated `scope`; the installer's `SCOPES` less `account-logs.read` and `connectivity-directory.bind` (each handled by its own step) are what every install needs.
